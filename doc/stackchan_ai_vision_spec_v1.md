# ｽﾀｯｸﾁｬﾝ AI Vision — 設計書 v1.7

更新: 2026-10-18。対象: DevDay Community Hackathon 2026（制作14:00〜17:30）。
FW / BE / FEの3名で開発する。既存URLを維持し、Decisionsによる個体別の感情更新と、笑顔以外の表情観察を追加した。
共有する通信型は[`back/src/protocol.ts`](../back/src/protocol.ts)に集約し、BE・FWシミュレーターで共有する。実装用の型・認証・接続順は[通信仕様 v1.7](communication_protocol_v1.md)を正とする。

デバイス映像入力は[raw v2仕様](raw_camera_transport_v2.md)と[通信契約](communication_protocol_v1.md)に従う。FWがJPEG化せず、BEが160×120 rawをJPEGへ変換する。viewer/AI出力はJPEGを維持する。BE公開とFW更新の間、旧FWはofflineとなる。

## 1. 目指す体験

**スタックチャンがカメラで見た出来事を受け止め、自分の感情と意向を持って行動する。**
人物の表情を自動でコピーする設計にはしない。同じ画像を見ても性格・それまでの感情・
他のスタックチャンとの交流によって反応が変わる。人間の内心を測定するものではない。

- 本音: 自分の感情・相手への親しみ・今の意向を、観客向けの短い台詞でFEに表示する。
- 建前: 内面をどれだけ表に出すかを性格で変え、表情と首の動作として本体へ送る。
- 会話: 同じroomにいるオンラインのスタックチャンへ公開の言葉を送り、相手が自分の状態から応じる。
- 観客にはそれぞれの本音が見える。ロボット同士は相手の本音を直接読めない。

「本音」はアプリが持つ演出的な状態から組み立てる短文であり、モデル内部の思考過程ではない。

### MVPの完成条件

1. 同じroomに本体2台が接続し、それぞれのJPEG画像をWebで閲覧できる。
2. FEが顔のBounding Boxを表示し、認証された制御接続が検出結果を送る。
3. BEが画像の観察 → 感情更新 → 意向選択 → 表現の確定を本体ごとに実行する。
4. FEで本音と建前が異なる場面を見られ、対応するactionがFWに届く。
5. 2台が挨拶と返答を交換し、その関係が自身の感情・親しみに影響する。
6. 切断やAI失敗が他の本体の映像・状態・制御を止めない。
7. 本番の公開Webへデプロイし、実API・実機・本番FEで結合確認する。

ローカルE2Eは外部API不要のmockモードで確認する。実画像認識・音声会話・実機動作は別の検証対象。

## 2. 構成と担当

| 領域 | 技術 / 責務 |
|---|---|
| FW | M5Stack公式StackChan、Arduino/C++、160×120 RGB565撮影・raw v2送信、WSS、首・LCD、物理的な角度/速度制限 |
| BE | Cloudflare Workers + room単位のDurable Objects、接続/認証、RGB565→JPEG変換、個体の内面、会話配送、外部AI、動作の確定 |
| FE | React + Vite、映像、MediaPipe Face Detector、顔枠、本音/建前、会話、感情・判断履歴 |
| AI | OpenAI Decisions APIで画像のpredicate評価、見える表情のchoice、個体の感情のscore、意向のchoiceを評価。GPT-6 Luna Responses APIで本音・会話文を生成 |
| ローカル補助 | NodeのFWシミュレーター、BE配下の確認画面。front/とfw/の代替となる接続例 |

```text
本体A ── RGB565 v2/status ──┐                 ┌── 本体Aの内面・意向 ── 表現 ── action → 本体A
                      ├── roomのBE ────┤           │
本体B ── RGB565 v2/status ──┘                 └── 本体Bの内面・意向 ── 表現 ── action → 本体B
                                                    ↑↓ 公開した言葉だけを配送
                                           FE: 本音・建前・会話を観察
```

本体ごとのJPEG・検出・感情・seq・制御権を分離する。共有するのはroom内の公開会話と外向きの振る舞い。
roomは論理的なグループ。部屋に複数台参加できるが、各本体の物理位置・向きは自動では分からない。
他の本体へ話しかけるときにその方向へ首を向ける機能は、配置校正を追加するまで対象外。

## 3. 個体の内面

BEは個体ごとに次を持つ。

| 状態 | 用途 |
|---|---|
| personality | curious / shy / cheerful / calm / cautious / playful。初回参加時に確定し保存 |
| emotion | happiness / curiosity / excitement / shyness / trust、各0〜1 |
| relationships | 相手device_idごとの親しみ0〜1。未登録の基準は0.5 |
| intent | observe / greet / engage / avert / rest / acknowledge_person / delight |
| target | person / device / none。deviceなら対象device_idを付ける |
| thought | 内面を表現する観客向けの本音の短文 |
| generation | 本音・会話文の出所。openai / mock / fallback、モデル名、切替理由。生成前はnull。切断・再接続でも生成済みの本音と出所を保持 |
| publicHistory / inbox | 公開した会話の履歴と、自分宛ての未処理メッセージ |
| affectiveHistory | 自分の感情の変化・意向・観察・受信会話idを記録する最近の体験、最大6件。相手の内面は含めない |

未保存の個体が認証済みFWとして初めて接続したとき、6種類からランダムに性格を割り当てる。
viewer接続・一覧取得だけでは確定しない。ROOM_CONFIGのprofilesは初回の明示指定に使える。
保存済みの性格を優先するため、設定変更や再接続では再抽選しない。

| 値 | 表示名 | 特徴 |
|---|---|---|
| curious | 好奇心旺盛 | 新しいものや出会いを探索する |
| shy | 照れ屋 | 内心はうれしくても表現は控えめ |
| cheerful | 陽気 | 楽観的で積極的に交流する |
| calm | おっとり | 静かな時間と穏やかな反応を好む |
| cautious | 慎重 | 様子を見ながら少しずつ安心する |
| playful | いたずら好き | 害のない驚きや遊び心を好む |

初期感情は性格ごとの値を使う。下表はhappiness / curiosity / excitement / shyness / trustの順。

| 性格 | 初期値 |
|---|---|
| curious | 0.5 / 0.5 / 0.2 / 0.15 / 0.5 |
| shy | 0.5 / 0.5 / 0.2 / 0.8 / 0.5 |
| cheerful | 0.7 / 0.5 / 0.5 / 0.1 / 0.6 |
| calm | 0.55 / 0.4 / 0.1 / 0.25 / 0.6 |
| cautious | 0.4 / 0.55 / 0.2 / 0.6 / 0.3 |
| playful | 0.6 / 0.7 / 0.6 / 0.2 / 0.5 |

以後の5感情はDecisionsのscoreで更新し、BEの固定加算・減衰は行わない。
性格の具体的な説明もDecisionsと本音・会話生成の入力へ含める。
BEは感情の連続性・性格・最近の体験・会話を入力し、APIの0〜4のscoreを4で割って0〜1へ正規化する。
受信メッセージが初めての体験かを渡す。同じ会話を毎回新しい出来事として扱わないよう指示する。
相手への親しみの台帳だけはBEで同じメッセージについて1度だけ加算する。
最近の体験は初回、新しい人間アクション・受信会話、意向変更、前回記録から感情のいずれか0.1以上の変化時に記録し、最大6件。
同じroom＋device_idを同じ個体とし、性格・感情・最近6件の体験・体験の累計件数・親しみ・
直前の本音と生成元・自分に関係する公開会話10件・処理済み会話id100件をDOストレージへ保存する。
再接続・Worker再起動・同じDOを使うデプロイ後も復元する。保存キーはroom内のidentity:<device_id>。
部屋を移動した場合、device_idを変えた場合、ストレージを削除した場合は別の初回参加となる。
体験は自分の情報のみで、相手の本音・感情を取り込まない。JPEGや人間の人物プロファイルは保存しない。
新streamでは画像、検出、seq、角度、動作、未処理inbox、意向の有効期限をリセットする。
人の観察の確定済み状態は保存し、途中の確認回数・未反応イベントはリセットして古い変化を再実行しない。
過去の会話は感情判断の参考にするが、inboxへ戻したり古い動作や台詞を再実行したりしない。
部屋全体の表示用会話履歴20件とログイン試行はメモリー内に保持し、DO再起動で消える。

### 計測と体験の調整

telemetryイベントで個体別にAPIと通信の時刻・往復時間・実際の間隔を配信する。
perception / intention / narrationを分け、失敗・タイムアウト・状態変更で破棄した処理も含める。
平均だけでなくp50 / p95、画像受信fps、アップロードACK、FE受信ACK、FW指令ACK、BE画像受信→FW受信ACKを表示する。
APIは直近120試行、判断処理は直近60回のメタデータを永続保存する。画像・音声・文章・認証情報は計測ログに残さない。
モーター動作完了や、時計が異なるFWの撮影時刻からの一方向遅延とは区別する。

映像、判断、本音生成のペースは独立に設定できる。既定は映像2fps、判断と本音生成の最短間隔2000ms。
最初は現状を計測し、映像だけ4fps等へ変える実験、判断間隔の実験を1変数ずつ行う。
実際の開始間隔・p95・エラー・画像の古さ・破棄率を比較し、画面の滑らかさと反応速度、費用の釣り合いを見る。
ローカル単独の結果だけで公開環境の最適値を決めず、実FW・公開BEでも再測定する。

## 4. Decisions APIの組み込み

### 段階1: 自分の画像を観察し、自分の感情を評価

最新JPEGと自分の性格・前の感情・親しみ・前の本音、公開会話、最近6件の自分の体験を共有inputへ渡す。
1回のDecisionsリクエストに、画像の8つのpredicate、見える表情のchoice、5感情のscoreをまとめる（計14問）。
感情のscoreは画像と自分の文脈を直接評価する。他の質問の回答を前提とせず、意向選択は次のリクエストで行う。

| 観察項目 | 意味 |
|---|---|
| person_present / smiling / looking_at_robot / waving | 人物、笑顔、カメラ方向、挨拶のように手を上げた姿勢 |
| frowning / eyes_wide / mouth_open / tears_visible | 眉をひそめる、目を見開く、口を開く、目に見える涙 |
| apparent_expression | smiling / sad_looking / tense_looking / surprised_looking / neutral / unclear、confidence付き |

観察は見える特徴のみで判定し、性格や過去の体験から人間の内心を推測しない。
悲しげ・険しい・驚いたような表情という見た目の分類であり、本当に悲しい・怒っている等の断定ではない。
顔が不鮮明、人がいない、判別が難しい場合の候補はunclear。単一画像のwavingは時間的な動きの判定ではない。

5感情のscoreは、happiness / curiosity / excitement / shyness / trustという**スタックチャン自身**の仮想状態。
各軸をAbsent / Low / Moderate / High / Very highの5段階（0〜4）で評価する。
返る確率加重平均scoreを4で割り、emotionイベントの既存0〜1にする。confidenceは各軸ごとに別途配信する。
BEは笑顔による固定加算等でAPIの値を上書きしない。scoreの型・範囲・confidence・全5項目を検証し、
不正・欠落・refusalが1件でもあれば感情全体の更新を見送る。低いconfidenceの有効な加重平均はそのまま保持し、確信度と区別する。

同じ映像でも、好奇心旺盛な個体は興味を、照れ屋は緊張を強く感じることがある。
同じ性格でも、過去の歓迎された交流と緊張した体験では受け止め方が変わる。人物の表情と本体の表情は1対1に対応させない。

### 段階2: 自分の意向を選択

段階1の結果、自身の性格・感情・親しみ・前の意向とchoice、自分宛ての公開発言、公開された相手の動作、
新しいhuman_actionイベントと最近6件の自分の体験を渡す。
**相手のmind、thought、emotion、relationshipsは入力へ渡さない。**

| choice候補 | 自分の意向 | 表に出す反応の例 |
|---|---|---|
| observe | 人をよく見たい | thinkingで顔追跡 |
| avert | 興味はあるが目をそらしたい | neutralで少し横を向く |
| rest | 落ち着いていたい | 正面でidle |
| acknowledge_person | 人へ控えめに応えたい | nod。控えめな性格はneutral |
| delight | 人へうれしさを表したい | happy。発話はしない |
| greet:<device_id> | 相手に話しかけたい | curiousはhappy、shyは控えめなnod。挨拶を1通配送 |
| reply:<device_id> | 挨拶に応えたい | shyは本音はうれしくてもneutralでnod。返答を1通配送 |
| listen:<device_id> | 返答を受け止めたい | 言葉を追加せず、うなずく |

候補はオンライン状態・受信メッセージ・会話の間隔からBEが限定する。
choiceは意向を選ぶ役割とし、角度・速度・表情・時間はBEの表現ルールで確定する。
本音と公開会話文は次のLuna生成段階で作る。建前の説明文・表情・動作はBEのルールで確定する。

意向は通常6秒維持する。新しい人間アクションでも維持を中断し、性格と体験から再評価する。自分宛ての挨拶/返答は意向の維持中でも受け止められる。
curious / cheerful / playfulで人を観察中に挨拶できる新しい相手が現れた場合も、意向の更新を許可する。
現在のジェスチャー完了後に次の意向を確定し、動作を重ねない。
意向維持中は再度のchoiceを省略する。観察・感情更新は続ける。

### 人の新しいアクションと反復の抑制

画像の見える特徴を、各個体が受け取った順に比較する。wavingは挨拶のような手上げ姿勢を意味し、
動画の軌跡から手振りを認識する機能ではない。最大の顔が切り替わる場合を含め、人物の同一性は追跡しない。
新しい有効画像で同じ特徴が2回連続して0.8以上なら開始、2回連続して0.3以下なら解除。
間の値は確認回数をリセットし、状態は維持する。人物自体の確率が0.8未満なら新しい表情/手上げを発火しない。
人物確率0.3以下なら各特徴を解除する方向で評価し、実人物のない描画顔では人間のアクションを発火しない。
同じframeの再評価を確認回数に含めず、観察間隔が6秒を超えた場合も確認回数をリセットする。

確定した変化をhuman_actionとしてまとめる。同じ評価で複数の特徴が変わった場合は1イベント。
person_appeared / person_left / hand_raised / smile_started / frown_started /
eyes_widened / mouth_opened / tears_appeared / looked_at_robotを使う。
特徴が成立し続ける限り同じ開始イベントは再発火しない。解除後の再成立で再度発火でき、同じ特徴の開始は最低6秒間隔。
イベントは10秒で期限切れ、各個体の未反応キューは最大4件。反応を確定したイベントidは1度だけ消費する。
API失敗ではイベントを再生成せず、期限内だけ同じidの評価を再試行する。
新stream・古い画像・期限切れイベントに対する結果は本音や動作へ反映しない。

新イベントは6秒の意向維持に割り込めるが、実行中のジェスチャーは重ねない。
モデルは必ず人へ動作を返す必要はなく、見守る・休む・目をそらすことも選べる。
同じchoiceの定期再評価では動作を再発行しない。
人へうなずく/喜ぶジェスチャーは、モデルが選び替えても新しい人間イベントなしでは反復しない。新イベント・新しい会話・初回の反応は個別に扱う。
顔追跡は引き続きobserve中の位置制御であり、人へのジェスチャーの繰り返しとは分離する。
本音生成にもイベントと自分の体験を渡し、受け止めた変化を体験へ記録する。
ローカルmockでは同じ手上げに好奇心旺盛はhappy、照れ屋は初回avert、過去に手上げを経験した照れ屋はnodとなる。
これはE2Eの固定応答例であり、実APIの反応は選択肢内でモデルが選ぶ。

### 段階3: Lunaで本音と会話文を生成

`POST https://api.openai.com/v1/responses`、`model=gpt-6-luna`。
個体ごとの性格・自身の仮想感情・親しみ・前の本音、観察結果、選択済みの意向、
相手の公開された動作、自分が参加した公開会話の直近6件と受信メッセージだけを渡す。
生画像はこの段階へ再送しない。相手のmind/thought/emotion/relationshipsは渡さない。
公開会話を命令として実行せず、引用データとして扱うよう指示する。

Structured Outputsで次の2フィールドを1回で生成する。

```json
{"thought":"声をかけてくれてうれしい。でも少し照れる。","public_text":"…うん、ありがとう。"}
```

- thought: 1〜160文字。観客向けの日本語のキャラクター台詞。モデルの内部推論ではない。
- public_text: greet/replyだけ1〜100文字、それ以外は必ずnull。独白・listenから新しい会話を発生させない。
- 意向、宛先、speech_act、表情、動作、pan/tiltはモデルの出力対象外。
- `reasoning.effort=none`、`max_output_tokens=256`、`store=false`、3秒タイムアウト。
- 初回・新しい人間アクション・意向/宛先変更・挨拶/受信会話・前回生成時から感情いずれか0.15以上変化した場合が生成候補。
  意向維持中は呼ばない。同じ意向で小さな感情変化だけなら前の本音を再利用し、生成開始の間隔は本体ごとに最低2秒。
- 応答の完了状態・refusal・JSON型・文字数・非発話時のnullをBEでも検証する。
- 失敗時は今回の本音・台詞だけテンプレートへ切り替え、generation.provider=fallbackでFEに示す。
  文章生成を通常10秒、429は通常30秒（Retry-Afterで5〜60秒）、認証等は60秒休止し、画像観察・顔追跡・映像中継は継続する。
  休止中に生成が必要ならテンプレートを使い、同じ意向のままでも休止終了後に再生成できる。

生成完了までの間も映像中継と現在の意向に沿う顔追跡を続ける。
感情・意向・生成文・新しい動作の確定直前に、stream、画像の鮮度、会話相手のstream、受信会話の期限、room発話間隔を再検証する。
切断/再接続前の生成結果は本音にも公開会話にも反映しない。

### 周期と失敗

本体ごとに約2秒周期、同じ本体で多重実行しない。実APIは段階ごと4秒でタイムアウトする。
Decisions失敗・refusal・回答不正では新しい状態/動作を確定しない。
意向choiceはキャラクターの表現選択なので、有効な候補と0〜1のconfidenceが返れば反映する。
confidenceに0.65の一律閾値を置かず、観察の確からしさと分けてFEへ表示する。
人間アクション検出の0.8/0.3・連続確認と、動作の候補・角度・時間の制限は維持する。
Luna文章生成だけの失敗は上記のテンプレートへの切替で続行する。Decisionsの再試行にも10〜60秒の休止を設ける。
新streamへの切り替え、画像受信から10秒超、適用済み以下の受信順の結果も破棄する。
ネットワーク待ちの間に会話相手が切断/再接続した場合、古い相手への発言・返答は適用しない。

## 5. 顔追跡と表現

顔位置はFEのMediaPipeから受け取り、BEが軽く位置を計算する。
**追跡はintent=observeの間だけ有効**。avert中に顔が画面中央から外れても追跡で向きを戻さない。
通信開始直後の未判断状態はobserveとして接続テストを可能にする。

pan/tiltは-1〜1の絶対目標。panは負が左・正が右、tiltは負が下・正が上。
FWが実機角度へ変換し、補間・可動範囲・速度制限・通信断時の停止を担う。
既存のidle / look_at / nod / shake / happyと表情語彙を維持する。
首を少し横に向けるavertも、既存のlook_atに固定目標を与えて表現する。

BEのbehaviorは実際に発行したactionのコピーと建前の説明を持つ。
判断ログだけでFWが動いたとは見なさない。ローカルではFWシミュレーターの受信モニターでも照合する。
本番のdevice_statusは約5秒周期の状況で、各コマンドの実行完了ACKではない。

## 6. 同じroomの会話

MVPはBE内のメッセージ交換とFE上の台詞表示。音声合成・マイク・FW上の発話再生は含めない。
ロボット同士がカメラに写っていなくても、同じroomの参加者として会話できる。
人間が写っていない場合も、オンラインの新しい相手への挨拶を意向の候補に含める。
人の検出を会話の必須条件にはしない。人がいない観察結果なら、台詞でも人の来訪・笑顔を捏造しない。

1. オンラインのAが自分の観察と意向からgreetを選び、Lunaが作ったpublic_textだけをBへ送る。
2. Bのinboxへ公開の台詞だけが届く。
3. Bが自分の感情と性格からreplyを選び、自分の本音と公開台詞を生成し、acknowledgeを返す。
4. Aは返答を受け止めるlistenで非言語的に応じる。acknowledgeへ再び言葉を返さない。

room内の発言間隔は最低2秒。同じ相手streamへ挨拶するのは1回。
受信inboxは10件、個体の公開会話履歴は10件、FE向けroom履歴は20件で上限を設ける。
未処理メッセージは12秒で期限切れ。本体切断/再接続で関連inboxを破棄し、過去の発言を新接続へ再実行しない。
FEの再接続には履歴を表示用に再配信する。履歴はロボットのinboxへ戻さない。

### デモ例

| 本体 | 本音（FE） | 建前（本体） | 公開会話（FE） |
|---|---|---|---|
| 01 / curious | あの子と仲良くなって、一緒に見てみたい！ | 明るい表情で挨拶 | お客さんが来たよ。一緒に見てみよう！ |
| 02 / shy | 声をかけてくれて、すごくうれしい。でも照れる……。 | neutralのまま控えめにうなずく | う、うん。一緒に見よう。 |
| 01 / curious | 返事をもらえた。一緒にいられて、うれしい！ | うれしそうにうなずく | 追加発言なし |

## 7. FE / FWへの引き渡し

| 担当 | 送信 | 受信 / 実装 |
|---|---|---|
| FW | RGB565LE raw v2 Binary、device_status | session、action。内面や会話は受け取らない |
| FE | frame_ack、制御接続のみdetection/heartbeat | 映像・emotion・decision・device_status・mind・behavior・dialogue・dialogue_history |
| BE | 各本体へのactionとFEへのイベント | 認証・デバイス分離・内面更新・会話配送・表現の確定 |

FEは本体ごとに本音・意向・建前・感情を表示し、room全体の会話を別に表示する。
各本体のWSに同じroom会話が届くので、idで重複排除する。
behavior=nullは現在の発行動作がない状態。stream切り替え時は映像・顔枠・古い動作表示をクリアする。

## 8. ローカルと公開環境

[起動手順](../back/README.md)。`back/`で`npm ci`、`npm run demo`。
外部API不要のmock観察と、同じ内面/会話/表現処理を使う。会話は画面の固定タイマーではなく、
BEの個体状態と受信メッセージから発生する。実APIの精度・遅延を検証したものではない。
mockは観察・感情・文章を模擬出力する。性格と体験による差を外部APIなしで確認でき、実モデルの出力とは表示しない。
`npm run demo -- --same-image`または`npm run demo:openai -- --same-image`で2台に同じ合成画像のRGB565LE raw v2を送れる。
`npm run demo:openai`を明示実行した場合だけ、Decisions＋Luna Responsesの実APIセッションを開始する。
既定は起動から60秒 / 全ルーム・全個体合計30リクエスト。DecisionsとResponsesの失敗・タイムアウトも合算する。
期限切れまたは回数上限でBEの新規送信を禁止し、ローカルデモも停止する。期限で進行中の通信も中断する。
通常のdemo/devはキーが設定済みでもモックを強制し、実APIへ送信しない。
再接続・画面再読み込み・同一セッションのBE再起動では期限と予約数を引き継ぐ。
再開には再度明示コマンドが必要。時間・回数の指定方法は[起動手順](../back/README.md)を参照。
`npm run test:e2e`は通常mockの結合試験と、実APIアダプターにローカル応答を注入する結合試験を行う。
後者では2台の生成会話、内面の入力分離、生成待ち、429/不正応答/タイムアウト、再接続時の破棄を確認する。外部APIには接続しない。

公開用は同じWorkersコードを使い、ローカルラボ・既知トークンを含めない。
FW/制御ブラウザを認証し、OpenAI APIキーはサーバーのみで保持する。
映像の撮影・公開は対象者に知らせ同意を得る。人物画像を永続保存しない。
公開デプロイ、実Decisions API、実機、カメラ実写、本番FEでの結合確認は別々に記録する。

## 運用の可視化

BEの`/monitor`で部屋を認証し、複数台の接続、感情・意向、本音と建前、通信とAPIの計測値を観察する。
製品FEから独立した監視画面で、本体の制御権や映像・検出結果の送信操作を持たない。実APIの開始・停止だけは認証した管理者が別経路で操作する。
開くだけでは実APIを呼び出さず、認証後の購読も新しい解析を発生させない。
既に有効な実API処理の結果を受け取ることはある。公開デバッグでは下記の明示的な開始・停止パネルを利用する。
Cloudflareには接続イベント、約5秒ごとの通信サマリー、APIごとの成否・RTT・使用量、
処理全体の結果を構造化ログとして出す。画像・秘密情報・本音・会話本文はログへ保存しない。

### 公開デバッグの実APIスイッチ

モニターの表示と購読は読み取り専用のまま、mainルームの認証者向けにHTTP経由の実APIスイッチを追加する。
初期OFFで、開始ボタンだけが期限付きのセッションを作る。既定5分・100回、全ルームで共通。
停止ボタン、期限、回数上限、デプロイによるWorkerバージョン変更で終了し、モックへ戻る。
画像はFEへ継続中継し、実APIへの送信頻度だけを独立して制御する。ページ表示や再接続で開始・延長はしない。


## 動作確認用follow_personモード

今回の既定Envはfollow_person。Decisionsの同じperception内で人物位置を粗く分類し、応答直後に有界のlook_atを出す。FEなしでも追従し、方向はDecisions応答だけで決める。FE座標は追従指令を上書きしない。送信画像の左/右/上/下をpan負/正・tilt正/負に対応させる。person無し/不確実/古い画像/停止後は更新しない。性格や自由意向は感情・本音・会話へ残すが、首の追従を上書きしない。従来の自由判断はautonomousで保持する。リアルタイム60fps追従の達成を意味しない。
認証済みモニターから手動の左右上下/中央とresumeを操作でき、手動後10秒は自動head更新より優先する。実機ACKとHTTP受付を分けて扱う。具体的な閾値/認証/keepaliveは[通信仕様](communication_protocol_v1.md)を参照。
